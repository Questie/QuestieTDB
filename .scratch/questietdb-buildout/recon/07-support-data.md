## 0. Executive shape

Four independent areas. In each, a **logic module** (`QuestieLoader:CreateModule`) stays in
Questie and a set of **data files** move to QuestieTDB. There is **no dynamic selection at
runtime** — per-flavor selection is done entirely by *which file the `.toc` lists*. Every
flavor's `.toc` names a different data file, and all of them assign to the **same** module
field. This is the single most important fact for packaging: QuestieTDB must ship
per-flavor `.toc`s that list exactly one variant of each file.

| Area | Logic module (stays) | Data files (move) | Data bytes on disk |
| --- | --- | --- | --- |
| Zones | `Database/Zones/zoneDB.lua` (430 ln) + `zoneDB.test.lua` (49 ln) | `Database/Zones/data/**` (8 files) | 248,139 |

### 1.2 Assignment targets and shapes

**Critical structural fact:** each of `areaIdToUiMapId.lua`, `uiMapIdToAreaId.lua`,
`subZoneToParentZone.lua` contains **two** tables: an *Override* table first (hand-authored),
then the *generated* table. Both are stored as **Lua long-string literals**
(`= [[return { … }]]`) that the logic module `loadstring()`s. They are **not** Lua tables at
load time — they are strings. `dungeons`, `zoneIDs`, `instanceIdToAreaId` are real tables.

### 1.3 How the logic module consumes the data — `Database/Zones/zoneDB.lua:38-77`

```lua
function ZoneDB.Initialize()
    HIDE_ON_MAP = QuestieQuestBlacklist.HIDE_ON_MAP
    areaIdToUiMapId = loadstring(ZoneDB.private.areaIdToUiMapId)()

    -- Override areaIdToUiMapId with manual overrides
    local areaIdToUiMapIdOverride = loadstring(ZoneDB.private.areaIdToUiMapIdOverride)()
    for areaId, uiMapId in pairs(areaIdToUiMapIdOverride) do
        areaIdToUiMapId[areaId] = uiMapId
    end

    uiMapIdToAreaId = loadstring(ZoneDB.private.uiMapIdToAreaId)()

    -- Override areaIdToUiMapId with manual overrides
    local uiMapIdToAreaIdOverride = loadstring(ZoneDB.private.uiMapIdToAreaIdOverride)()
    for areaId, uiMapId in pairs(uiMapIdToAreaIdOverride) do
        uiMapIdToAreaId[areaId] = uiMapId
    end

    dungeons = ZoneDB.private.dungeons

    subZoneToParentZone = loadstring(ZoneDB.private.subZoneToParentZone)()

    -- Override subZoneToParentZone with manual overrides
    local subZoneToParentZoneOverride = loadstring(ZoneDB.private.subZoneToParentZoneOverride)()
    for areaId, parentZoneId in pairs(subZoneToParentZoneOverride) do
        subZoneToParentZone[areaId] = parentZoneId
    end

    -- Run tests if debug enabled
    if Questie.db.profile.debugEnabled then
        _ZoneDB:RunTests()
    end

    for areaId, dungeonZoneEntry in pairs(dungeons) do
        local alternativeDungeonZone = dungeonZoneEntry[2]
        if alternativeDungeonZone then
            alternativeDungeonAreaIdToDungeonAreaId[alternativeDungeonZone] = areaId
        end
    end
end
```

    dungeons[2597][4] = {(isHorde and {267, 58.4, 33.3}) or {267, 44.5, 46}} -- Alterac Valley

**Implication for ticket 12:** `dungeons.lua` cannot be baked to a single static table
without either (a) shipping five expansion variants × two faction variants, or (b) keeping
the conditional logic in Questie and shipping only the base table. Option (b) matches
DESIGN's "only the data moves — the modules that wrap it stay with the consumer"; the base
table is 125 entries / 11 KB. Recommendation: ship the base literal, keep the two
`if Expansions.Current >=` blocks and the `isHorde` ternaries in Questie's `zoneDB.lua`
(or a small `dungeonOverrides.lua` that stays).

        DropDB.tablePserver = loadstring(QuestieTBCItemDrops.cmangosData)()

        DropDB.tableWowhead = loadstring(QuestieWotlkItemDrops.wowheadData)()
        DropDB.tablePserver = loadstring(QuestieWotlkItemDrops.cmangosData)()
        DropDB.sourcePserver = "cmangos"
    elseif Questie.IsCata then

        DropDB.tablePserver = loadstring(QuestieCataItemDrops.mangos3Data)()

#### Relation to the corrections system

- **Same mental model, entirely separate machinery.** Questie's entity corrections go
  through `Database/Corrections/QuestieCorrections.lua` — `QuestieCorrections:Initialize`
  calls `_LoadCorrections("questData", …Fixes:Load(), QuestieDB.questKeysReversed,
  validationTables)` per expansion (lines 258-311), with the same
  `if Expansions.Current >= Expansions.Tbc / Wotlk / Cata / MoP` cascade. Drop corrections
  bypass all of that: they are merged inline inside `DropDB:Initialize()`
  (`dropDB.lua:68-80`).
- **Different unit of override.** `_LoadCorrections` merges *per field*; drop corrections
  merge *per item* (`DropDB.tableCorrections[k] = v` replaces the whole `{npcId=rate}` map).
- **Different applicability.** Entity corrections are baked into entity data (ticket 09/11 —
  build-time, never shipped). Drop corrections are *runtime lookup overlays* on tables the
  consumer queries, and they carry a **sentinel indirection** (`-1`/`-2`) that must be
  resolved against whichever pserver/wowhead table was selected at init. They cannot simply
  be pre-applied into the drop tables without losing that indirection semantics — a
  `WOWHEAD` correction means "prefer the wowhead value over the pserver value", which is a
  *precedence* statement, not a value.
- Two consistent ways to satisfy ticket 12 bullet 5:
  1. Register it in QuestieTDB's corrections registry as a **Static Correction over drop
     data** and bake the result — requires eliminating the `-1`/`-2` sentinels by resolving
     them at generation time (possible: the generator knows which wowhead/pserver table each
     flavor uses). Output would be one flat `table<ItemId, table<NpcId, float>>` per flavor
     plus a source tag, collapsing `tableCorrections`/`tablePserver`/`tableWowhead` into
     one. This deletes `DropDB.correctionKeys` and the precedence code in
     `dropDB.lua:120-142`.
  2. Ship it as **data** alongside the drop tables, but declare it in the corrections
     registry so it is discoverable/owned, and keep the resolution code in Questie.
     Cheapest; keeps `dropDB.lua` byte-identical.

## 9. Gotchas — things that will break a naive implementation

1. **Zone tables are strings, not tables.** `ZoneDB.private.{areaIdToUiMapId,
   areaIdToUiMapIdOverride, uiMapIdToAreaId, uiMapIdToAreaIdOverride, subZoneToParentZone,
   subZoneToParentZoneOverride}` are `[[return { … }]]` long strings that `zoneDB.lua`
   `loadstring()`s. `ZoneDB.private.dungeons`, `ZoneDB.zoneIDs`,
   `ZoneDB.instanceIdToAreaId`, `QuestXP.db`, `QuestieDB.factionTemplate` are **real
   tables**. Getting this backwards breaks `Initialize()` at load.
2. **Six zone fields, not three.** Each of the three zone mapping files defines BOTH a
   generated table and a hand-authored `…Override` table, in the SAME file, and both must
   be shipped. The override is applied *on top* after `loadstring`.
3. **`ZoneDB.private.subZoneToParentZoneOverride` is read a second time outside
   `Initialize`** — `Modules/Journey/tabs/QuestsByZone/QuestsByZoneTab.lua:139` calls
   `loadstring(...)()` on it on every dropdown build. It must stay a string.
4. **`dungeons.lua` is not static data.** It branches on
   `local isHorde = UnitFactionGroup("Player") == "Horde"` (line 5, entries 2597/3277/3358)
   and mutates itself under `if Expansions.Current >= Expansions.Wotlk` (lines 143-147) and
   `>= Expansions.Cata` (lines 149-185). Baking a single table per flavor loses the
   faction dimension; baking per-faction doubles it. Recommend shipping the base literal and
   leaving the conditionals in Questie.
5. **MoP UiMapIds are a different numbering space.** `[1] = 1426 -- Dun Morogh` (non-MoP) vs
   `[1] = 27 -- Dun Morogh` (MoP). The MoP variants live in `Zones/data/MoP/` and assign to
   the *same* `ZoneDB.private.*` fields. Loading both would silently clobber. Only two of
   the eight zone data files are MoP-specific.
6. **`instanceIdToAreaId.lua` reads `ZoneDB.zoneIDs.X` at file-load time** — `zoneIds.lua`
   must execute first (TOC lines 62 then 63). Similarly `itemDropCorrections.lua:9` reads
   `DropDB.correctionKeys` at load time — `dropDB.lua` must execute first (TOC lines
   e.g. 127 then 128 for Classic).
7. **`QuestieLoader:ImportModule` silently creates an empty stub** if the module does not
   exist yet (`Modules/Libs/QuestieLoader.lua:26-33`). So a wrong load order does NOT error —
   it yields `nil` field reads at load time. Failures are silent-then-late.
8. **MoP ships two drop-data files and reads a third module's field.**
   `Questie-Mists.toc` loads `mopItemDrops.lua` AND `cataItemDrops.lua`, and
   `dropDB.lua:58` does `loadstring(QuestieCataItemDrops.mangos3Data)()` in the MoP branch.
   Dropping `cataItemDrops.lua` from the MoP package breaks pserver drop rates for MoP.
9. **`QuestieMopItemDrops.cmangosData` is an empty table (`[[return {\n\n}]]`) that nothing
   reads.** 0 items. Do not "fix" it by wiring it in — `dropDB.lua` deliberately uses cata
   mangos3 there.
10. **Field name inconsistency:** four drop files use `.cmangosData`; `cataItemDrops.lua`
    uses **`.mangos3Data`**. Any generator/loader keyed on a single name will miss Cata.
11. **`DropDB.tableCorrections = QuestieItemDropCorrections.Era` is an ALIAS, not a copy**
    (`dropDB.lua:68`). The subsequent merge loops mutate `QuestieItemDropCorrections.Era`
    in place. Calling `DropDB:Initialize()` twice, or reading
    `QuestieItemDropCorrections.Era` afterwards, gives polluted data.
12. **Drop-correction merge is per-ITEM, not per-item:npc.**
    `DropDB.tableCorrections[k] = v` replaces the whole `{npcId=rate}` map. Four items
    appear in both `Era` and `Tbc` — **2633, 12335, 12336, 12337** — and TBC's map wholly
    replaces Era's. E.g. item 2633 loses Era's NPC 940/941/942 entries in favour of TBC's
    937/940/941/942 set; 12335/12336/12337 flip from `10` to `100`.
13. **`DropKeys.PSERVER` (`-2`) is documented but never used.** Only `WOWHEAD` (`-1`) and
    literal floats appear. Do not assume both branches are exercised.
14. **`QuestieItemDropCorrections.Wotlk` and `.Cata` are empty (`{}`)** — the cascade still
    iterates them. Do not treat empty as "file missing".
15. **XP level sentinel `-1`.** `QuestXP:GetQuestLogRewardXP` returns 0 when `level <= 0` or
    `xp <= 0`. Cata/MoP use `{1, 0}` filler rows in bulk (thousands of them) — those tables
    are ~3-5× larger in entry count but *smaller* in bytes than classic/tbc/wotlk because
    the latter carry per-row provenance comments.
16. **`QuestieDB.factionTemplate` has no initialiser.** The data file assigns it directly at
    load. If QuestieTDB defers it behind a getter, `Townsfolk.lua:617-622` breaks (it indexes
    the raw table).
17. **`Questie.toc` (Interface `00000`) loads none of this** — it is the
    unsupported-client stub. Don't mirror it.
18. **SoD reuses the Classic TOC entirely.** There is no SoD support-data variant. Anything
    keyed on "5 flavors" is correct for support data; anything keyed on "6 databases
    including SoD" is not.
19. **`zoneIds.lua` in the prototype (`Getters/GetterDB/Meta/ZoneMeta.lua`) has 32 conflicting
    values** vs Questie, e.g. `BLACKROCK_DEPTHS_SHADOWFORGE_CITY` = **1585** (Questie) vs
    **10002** (prototype), `NAXXRAMAS_ARACHNID_QUARTER` = **10063** vs **4839**,
    `END_TIME_RUBY_DRAGONSHRINE` = **5790** vs **10035**, plus all the ICECROWN_CITADEL_*,
    UTGARDE_*, GUNDRAK_*, BAND_OF_* families. It also invents `EASTERN_KINGDOM = 0`,
    `SOUTH_SEAS`, `THE_GILDED_GATE`, `LOWER/UPPER_BLACKROCK_SPIRE` etc. that Questie does
    not have, and is missing 162 of Questie's names. **Questie's `zoneIds.lua` wins.**
20. **`cli/apiMocks.lua`'s `UnitFactionGroup` is `function() return arg[1] or "Horde" end`**
    — `arg` is the *command-line* argument table, not the function parameter. Headless loads
    of `dungeons.lua` therefore get Horde coordinates unless a CLI arg is passed. If
    QuestieTDB bakes dungeons, the generator must not inherit this accident.
21. **`ZoneDB.Initialize` reads `Questie.db.profile.debugEnabled`** (line 67) — a nil
    `Questie.db.profile` throws. Any headless loader must set
    `Questie = {db = {profile = {}}}` first.
22. **`ZoneDB:GetAreaIdByUiMapId` calls `error()`** when nothing matches (line 134) and uses
    `C_Map.GetMapInfo` / `C_Map.GetAreaInfo`. `apiMocks.lua` leaves `C_Map = {}`. Validators
    only use `GetUiMapIdByAreaId`, which is safe.
23. **`itemDropCorrections.lua` is listed in every flavor's `.toc`** (5 copies of the same
    22 KB file's cost is 1 file, but it ships to all 5 packages). It is currently the only
    "corrections" file outside `Database/Corrections/` — that mislocation is precisely what
    ticket 12 bullet 5 is asking to reconcile.
