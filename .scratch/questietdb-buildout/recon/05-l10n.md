### Format facts

| Question | Answer |
|---|---|
| Client-locale guard | `if GetLocale() ~= "<LOCALE>" then` / `    return` / `end` — **lines 1-3, byte-identical in all 180 files** (verified: 9 distinct line-1 strings × 20 files each) |
| Assignment target | `l10n.<field>["<LOCALE>"]` where field ∈ `questLookup`, `npcNameLookup`, `objectLookup`, `itemLookup` (verified exactly 1 assignment per file, 180/180) |
| Payload form | **`loadstring([[return { … }]])`** — the value assigned is a **function**, not a table. `l10n.questLookup["deDE"]` is a `function` that returns the table when called. This is uniform: all 180 files, all 4 types. |
| Long-bracket level | Always plain `[[ … ]]` (level 0). No `[=[` anywhere. |
| Import line (line 6) | `local l10n = QuestieLoader:ImportModule("l10n")` — identical in all 180 |
| Annotation (line 5) | **NOT uniform**: 144 files use `---@type l10n`, **36 files use `-- - @type l10n`** (broken annotation, cosmetic only). The 36 are all of `Cata/lookupItems/*`, `Cata/lookupNpcs/*`, `Wotlk/lookupItems/*`, `Wotlk/lookupNpcs/*` (9 locales × 4 dirs). |
| Extra header text | `MoP/lookupQuests/esMX.lua` and `MoP/lookupQuests/zhTW.lua` insert 3 extra lines before the assignment: blank / `-- ! THIS IS A RAW COPY OF THE CATA DATA, NOT AN ACTUAL MOP DUMP` / blank — so their assignment is on **line 12, not line 8**. Do not hardcode line 8. |

Objective lines (`row[2]`) are a **contiguous numeric-indexed array of strings** — verified

## 4. Loading all nine locales in ONE generation run

### 4.1 The guard, quoted verbatim from four different locale files

`Localization/lookups/Classic/lookupQuests/koKR.lua:1-3`
```lua
if GetLocale() ~= "koKR" then
    return
end
```
`Localization/lookups/Wotlk/lookupObjects/ruRU.lua:1-3`
```lua
if GetLocale() ~= "ruRU" then
    return
end
```
`Localization/lookups/MoP/lookupItems/zhCN.lua:1-3`
```lua
if GetLocale() ~= "zhCN" then
    return
end
```
`Localization/lookups/Cata/lookupNpcs/ptBR.lua:1-3`
```lua
if GetLocale() ~= "ptBR" then
    return
end
```

**Uniformity proof**: `head -1` over all 180 files yields exactly 9 distinct strings,
20 occurrences each (one per expansion×type). The guard is a *top-level early return from the
chunk*, so once `GetLocale()` matches, the rest of the file executes.

### 4.2 What must be stubbed

Only **two globals**:

1. `_G.GetLocale` — a closure over a mutable upvalue you flip before each `loadfile`.
2. `_G.QuestieLoader` — needs only `ImportModule(name)` returning the l10n table. The files
   never inspect the argument.

Nothing else is touched: no `Questie`, no `QuestieDB`, no WoW API. `loadstring` is standard
Lua 5.1 and works as-is (in Lua 5.2+ you must alias `loadstring = load`).

### 4.3 What must be RESET between files

The assignment is `l10n.<field>["<locale>"] = <function>`, keyed by locale — so writes for
different locales do **not** collide, and in principle one shared `l10n` table could
accumulate all nine. **But reset anyway**, because:

* If `GetLocale()` and the file's locale ever disagree the file silently no-ops, and with a
  shared table you would read a *stale sibling locale's* function and not notice. With a fresh
  table per file, `type(l10n[field][locale]) ~= "function"` is a hard error.
* The returned closure is memory-heavy; calling it materialises a table of up to 88 183 rows.
  Drop the reference after each file so GC can reclaim it.

### 4.4 Working harness (verified — this exact pattern loaded all 180 files successfully)

```lua
local ROOT = ".../Questie/Localization/lookups/"
local EXPANSIONS = {"Classic","TBC","Wotlk","Cata","MoP"}
local LOCALES    = {"deDE","esES","esMX","frFR","koKR","ptBR","ruRU","zhCN","zhTW"}
local KINDS = {
  {dir="lookupQuests",  field="questLookup"},
  {dir="lookupNpcs",    field="npcNameLookup"},
  {dir="lookupObjects", field="objectLookup"},
  {dir="lookupItems",   field="itemLookup"},
}

local l10n, currentLocale
_G.GetLocale      = function() return currentLocale end
_G.QuestieLoader  = { ImportModule = function() return l10n end }

local function LoadLookup(expansion, kind, locale)
  local path = ROOT .. expansion .. "/" .. kind.dir .. "/" .. locale .. ".lua"
  l10n = { questLookup = {}, npcNameLookup = {}, objectLookup = {}, itemLookup = {} }  -- RESET
  currentLocale = locale                                                               -- RESET
  local chunk = assert(loadfile(path))
  chunk()
  local fn = l10n[kind.field][locale]
  assert(type(fn) == "function", path .. " did not register a lookup for " .. locale)
  return fn()   -- the table
end
```

The upstream reference implementations of this exact pattern:
* `Localization/lookups/<Exp>/lookupLoadstrings.test.lua` — `before_each` at ~line 116 builds
  a fresh `l10n = {itemLookup={}, npcNameLookup={}, objectLookup={}, questLookup={}}`, stubs

  `describe("<locale>")` block sets `_G.GetLocale = function() return "<locale>" end`.

### 5.2 `l10n:Initialize()` — `Localization/l10n.lua:45-97` (verbatim)
```lua
function l10n:Initialize()
    local itemLookup = l10n.itemLookup[locale] and l10n.itemLookup[locale]() or {}
    for id, data in pairs(l10n.itemLookupOverrides and l10n.itemLookupOverrides() or {}) do
        itemLookup[id] = data
    end

    local questLookup = l10n.questLookup[locale] and l10n.questLookup[locale]() or {}
    for id, data in pairs(l10n.questLookupOverrides and l10n.questLookupOverrides() or {}) do
        questLookup[id] = data
    end

    local npcNameLookup = l10n.npcNameLookup[locale] and l10n.npcNameLookup[locale]() or {}
    local objectLookup = l10n.objectLookup[locale] and l10n.objectLookup[locale]() or {}

    -- Load item locales
    for id, name in pairs(itemLookup) do
        if QuestieDB.itemData[id] and name then
            QuestieDB.itemData[id][QuestieDB.itemKeys.name] = name
        end
    end

    -- data is {<questName>, {<questObjective>, ...}}
    -- Load quest locales
    for id, data in pairs(questLookup) do
        if QuestieDB.questData[id] then
            if data[1] then
                QuestieDB.questData[id][QuestieDB.questKeys.name] = data[1]
            end
            if data[2] then
                QuestieDB.questData[id][QuestieDB.questKeys.objectivesText] = data[2]
            end
        end
    end

    -- Load NPC locales
    for id, data in pairs(npcNameLookup) do
        if QuestieDB.npcData[id] and data then
            if type(data) == "string" then
                QuestieDB.npcData[id][QuestieDB.npcKeys.name] = data
            else
                QuestieDB.npcData[id][QuestieDB.npcKeys.name] = data[1]
                QuestieDB.npcData[id][QuestieDB.npcKeys.subName] = data[2]
            end
        end
    end

    -- Load object locales
    for id, name in pairs(objectLookup) do
        if QuestieDB.objectData[id] and name then
            QuestieDB.objectData[id][QuestieDB.objectKeys.name] = name
        end
    end
end
```

**Critical semantics for the overlay replacement:**
* Writes are **in-place mutations of `QuestieDB.questData` / `npcData` / `objectData` /
  `itemData`** (already-`loadstring`'d Lua tables) **before compile**.
* Quest: name and objectivesText each guarded by `if data[N] then` → a nil translation leaves
  the enUS base value. **Fallback-to-base is already the behaviour.**
* Npc: **NOT individually guarded.** `subName` is assigned unconditionally to `data[2]`, so a
  translated NPC with no localized subName **wipes the enUS subName to nil**. Reproducing
  current behaviour exactly means the npc subName overlay must clear, not fall back. (A
  fallback-to-base overlay is arguably a *fix*, but it is a behaviour change — flag it.)
* Npc branch tolerates a bare `string` value (`type(data) == "string"`). No file in the tree
  actually uses that form today — it is dead legacy tolerance.
* Only ids already present in the base DB are written (`if QuestieDB.<x>Data[id]`), so
  lookup ids with no base entity are dropped silently.
* Overrides (`lookupOverrides.lua`) are merged into `itemLookup`/`questLookup` **by whole row
  replacement** before the write loop. There are no npc/object overrides.

### Escape sequences in the raw source (what to expect when re-emitting)

The payload is `[[…]]` at the outer level (backslash literal) but the *inner* text is Lua
source with `"…"` strings, so backslashes there **are** escapes. Raw two-char sequences
present across all data files:
```
\"   24838   escaped double-quote inside a name / objective line
\\      35   literal backslash (decodes to \)   e.g. Cata/lookupItems/frFR.lua:16841
\5      39   decodes to byte 0x05               e.g. TBC/lookupItems/frFR.lua:30877
\n      19   decodes to newline 0x0A            only Classic/lookupQuests/esMX.lua:{456,2371,2405}
```
No `\r`, `\t`, `\ddd` other than `\5`. A generator that re-emits Lua source must escape at
minimum `"`, `\`, and any byte `<0x20`/`0x7F`.

### Pipe `|` characters
Present in raw source of some quest files (e.g. `Wotlk/lookupQuests/esMX.lua` 256 lines,
`Cata/lookupQuests/esMX.lua` 211). These are WoW escape/UI sequences (`|c`, `|r`, `|4`) or
literal pipes in text. `|` is **not** a safe separator for this data.

## Prototype divergences (informational — prototypes are stale, Questie is truth)

* **Locale order differs between prototypes and QuestieTDB config.** `Getters/src/get/l10n.lua:39`
  uses `{ "ptBR", "ruRU", "deDE", "koKR", "esES", "esMX", "frFR", "zhCN", "zhTW" }`, while
  `QuestieTDB/src/config.lua:79` uses `{ "deDE", "esES", "esMX", "frFR", "koKR", "ptBR",
  "ruRU", "zhCN", "zhTW" }`. Order is load-bearing (the decoder captures the Nth segment).
  Do not copy the Getters order.
* `toc-database/src/config.lua:19-48` field contract: Item `{name}`, Npc `{name, subName}`,
  Object `{name}` (`scalar = true`), Quest `{title(1), objectives(2)}` with
  `description/details/requestItems/offerReward/endText` commented out. Matches Questie's four
  fields; `title` is Questie's `name`, `objectives` is Questie's `objectivesText`.
* `Getters/data/l10n/Era/l10nQuestData.lua-table` rows are `{{ nameJoined, nil, objectivesJoined }}`
  — i.e. the prototype reserved index 2 and put objectives at index 3, and it collapsed the
  **objective line array into a single string per locale**. Questie's real data has up to
  15 lines with meaningful empties. Verify how QuestieTDB intends to encode the list dimension
  before assuming a flat locale-join is sufficient.
* `QuestieTDB/docs/storage-format.md:98` and `QuestieTDB/src/config.lua:80` both fix the
  separator at `‡` U+2021 — confirmed collision-free against the real data (0 occurrences).

Assert: type(l10n[field][locale]) == "function" after each load.
